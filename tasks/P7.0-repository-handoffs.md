# P7.0 — Repository-Backed Multi-Agent Handoffs

- **Status:** Review
- **Owner/orchestrator:** Project owner + ChatGPT
- **Implementation agent:** ChatGPT
- **Target branch:** `main`
- **Working branch:** `feat/repository-handoffs`

## Objective

Standardize cross-agent continuation around one repository-backed handoff file:

- `docs/HANDOFFS.md` is the canonical handoff log and policy;
- each meaningful transfer of responsibility appends one compact, uniquely identified handoff section;
- `docs/STATUS.md` stores only the active handoff ID;
- the next agent reads only the active handoff section, not the entire handoff history.

## Context

Multi-agent work currently relies too heavily on chat copy/paste. The repository already separates current operational state (`docs/STATUS.md`) from durable decisions (`docs/PROJECT-MEMORY.md`). Handoffs need the same repository-backed treatment without turning STATUS into a transcript or loading historical handoffs into every agent session.

The intended continuation flow is:

```text
agent finishes bounded work
→ append compact handoff section to docs/HANDOFFS.md
→ update docs/STATUS.md: Active handoff: <ID>
→ next agent reads startup context + only that handoff section
→ continue from exact repository state
```

## Forbidden scope

- replacing STATUS, task contracts, or PROJECT-MEMORY with handoffs;
- loading the entire handoff log during routine startup;
- storing raw logs, secrets, credentials, sensitive production/customer data, or full diffs in handoffs;
- weakening existing CI, security, review, merge, or release gates;
- making handoffs a substitute for durable architecture/product decisions;
- merging without explicit owner approval.

- [x] Project Baseline requires `docs/HANDOFFS.md` as a core file.
- [x] Template Integrity requires `docs/HANDOFFS.md`.
- [x] Validator self-tests continue to pass and explicitly confirm HANDOFFS is core.

## Required validation

- **Test objective:** prove HANDOFFS is part of the core operating model, selected-project validation still works, and the new startup/continuation rules do not duplicate detailed policy.
- **Minimum automated evidence:**
  - `python scripts/test_validate_project_profile.py`
  - `python scripts/validate_project_profile.py --repository mrdzyn/ai-native-project-template`
- **Manual QA:** inspect startup order, STATUS semantics, handoff template, greenfield cleanup, and policy duplication.
- **Escalation triggers:** broaden only if validator/CI behavior changes unexpectedly or review finds ambiguity between HANDOFFS, STATUS, tasks, or PROJECT-MEMORY.
- **Required CI:** Project Baseline CI and Template Integrity at exact PR head.

## Security / privacy considerations

Handoffs must contain concise operational metadata only. Never store secrets, credentials, private keys, sensitive production/customer data, or unnecessary personal data. Link to authoritative repository artifacts rather than pasting large sensitive/log outputs.
