# P5.1 — Test-Budget Observability

- **Status:** Draft
- **Owner/orchestrator:** Unassigned
- **Target branch:** `main`

## Objective

Make the token/time savings from objective-based testing measurable without imposing unsafe one-size-fits-all test-count limits.

## Problem

The Phase 5 stop rule is intentionally qualitative because test depth depends on risk and blast radius. That preserves safety, but it does not yet provide a quantitative way to verify that AI agents are actually reducing unnecessary test work.

## Proposed scope

Evaluate lightweight metrics that do not require storing sensitive prompts or model internals, such as:
- number of agent-invoked local test commands per task;
- repeated execution count of an unchanged suite;
- targeted-test vs full-suite executions;
- local validation elapsed time when readily available;
- reason code when testing escalates beyond the task's minimum evidence;
- required-CI executions tracked separately from agent/local validation.

Where model/platform token-usage telemetry is available safely, assess whether it can be captured at an aggregate task level without coupling the template to one vendor.

## Guardrails

- Do not set arbitrary global limits such as "maximum N tests" for all tasks.
- High-risk and release work must be free to exceed normal budgets when justified.
- Do not collect prompts, secrets, source code, customer data, or sensitive logs merely to measure testing efficiency.
- Metrics must distinguish agent/local validation from required CI.
- The purpose is observability and tuning, not rewarding fewer tests regardless of risk.

## Success criteria

A future implementation should make it possible to compare before/after testing efficiency for representative small, medium, and high-risk tasks while preserving defect-detection and mandatory CI/release gates.

## Deliverable

Propose a minimal measurement schema and pilot it on several real projects before adding any default quantitative thresholds.
