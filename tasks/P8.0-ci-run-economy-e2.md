## Goal

Reduce the master-template CI from two automatic PR runners to one **without weakening required master integrity validation or deadlocking protected `main`**. E2 is a staged cutover. E2a is a shadow-validation PR, **not** the ruleset cutover.

## E2a scope — shadow validation (this PR)

Allowed paths:
- `scripts/validate_master_template.py` (new master-only deterministic inventory/profile validator, extracted from existing workflow);
- `.github/workflows/common-validation.yml` (two master-guarded steps in the existing runner);
- `.github/workflows/template-integrity.yml` (existing required job calls that same script; job remains intact);
- `docs/REPOSITORY-SETUP.md` (cutover contract);
- `docs/STATUS.md`, `docs/HANDOFFS.md`, this task (handoff/bookkeeping).

Forbidden in E2a: live ruleset changes; removing/skipping `Template integrity`; changing `ci.yml` caller, required check names, scripts/profile schema, release/deployment/secrets/OIDC; merging without owner approval.

### Target architecture in E2a

```text
pull_request
├── Project baseline / Common validation [REQUIRED; one runner]
│   ├── universal profile validation and lightweight env guard
│   └── only if canonical master repository:
│       ├── scripts/validate_master_template.py
│       └── scripts/test_validate_project_profile.py
└── Template integrity [STILL REQUIRED; existing second runner]
    ├── scripts/validate_master_template.py
    └── scripts/test_validate_project_profile.py
```

Both paths use the same master inventory script. Fail-closed semantics for malformed/missing master inventory, wrong template mode and invalid design tokens remain intact. Master-only guarded steps must skip for all child repos.
