# P6.0 — Brownfield Reconciliation & Greenfield Pruning

- **Status:** Review
- **Owner/orchestrator:** Project owner + ChatGPT
- **Implementation agent:** ChatGPT
- **Target branch:** `main`
- **Working branch:** `feat/project-reconciliation-pruning`

## Objective

Make project adoption deterministic and low-noise:

- **Brownfield:** reconcile the template with existing authoritative project guidance without creating duplicate or ambiguous instructions.
- **Greenfield:** remove inherited master-only and unselected optional template artifacts that are not part of the project.

## Context

The operating model already supports capability selection and preserves stronger brownfield guidance, but adoption/pruning is not explicit enough. Mature repositories can end up with two competing sources for testing, security, architecture, status, or agent instructions. New repositories can retain dormant template documents that are not selected by the project profile, increasing noise and agent context cost.

The goal is to standardize one canonical source per concern while keeping the master template complete.

## Forbidden scope

- removing optional capability files from the master template itself;
- weakening required CI, security, review, merge, or release controls;
- overwriting stronger project-specific brownfield guidance merely to match template filenames;
- requiring duplicate canonical documents for the same concern;
- making Project Baseline fail solely because an unselected optional template artifact is still present;
- introducing project-specific stack/product assumptions into the master template;
- merging without explicit owner approval.
