## Purpose and test objective

After the owner-approved live required-check cutover, eliminate **one redundant automatic master CI runner per PR update** by making the standalone Template Integrity workflow manually dispatchable only. **Prove** a real PR emits the required `Project baseline / Common validation` context, and within that runner actually executes master inventory and capability self-tests, **without** an automatic `Template Integrity` run. This reduces runner-job starts from two to one for the master template's two prior PR workflows; it does not guarantee 50% fewer *billed minutes*.

- The human owner explicitly approved a separate ruleset edit. GitHub read-back of active `Protect Main` ruleset `23809419` on 2026-10-14 confirmed that only `Project baseline / Common validation` (GitHub Actions integration `15368`) remains required.
- The ruleset still enforces PR protection, discussion resolution, zero GitHub-required approvals, and unchanged admin PR-only bypass.
- Common baseline already runs `scripts/validate_master_template.py` and `scripts/test_validate_project_profile.py` on the canonical master; PR #22 provided post-E2a hosted CI evidence that these steps actually pass.
- Owner accepted Option B's residual risk: external Claude exact-head audits and human owner merge authorizations are **process-only**, not enforced by GitHub; a lone check cannot independently detect removal of its own steps.

## Scope

Allowed paths:
- `.github/workflows/template-integrity.yml` — remove **only** `on.pull_request`, keep `on.workflow_dispatch`;
- `docs/STATUS.md`, `docs/HANDOFFS.md`, `docs/REPOSITORY-SETUP.md` — record true cutover state/risks;
- this task spec.

Forbidden: any live ruleset change, `.github/workflows/ci.yml`, `.github/workflows/common-validation.yml`, validator/script, app/release, secrets/OIDC, CODEOWNERS/collaborator, branch bypass, merge or deployment change.

## Acceptance

1. Workflow has **only** `workflow_dispatch` trigger; retain existing master repository guard, job name `Template integrity`, pinned checkout, `contents: read`, shell fail-fast, inventory and profile self-tests.
2. New PR's `Project baseline / Common validation` **emits and succeeds** on the exact SHA (real GitHub runner). Inspect steps/logs confirming both `Complete master-template inventory is valid.` and `Project capability profile self-test matrix passed.` as well as the universal baseline validation.
3. The standalone `Template Integrity` workflow **does not automatically run for the PR**. Verify GitHub's full PR workflow-run set; do not mistake a manually dispatched run for a PR-triggered run. Do not claim absence unless actually verified.
4. Live ruleset continues to require `Project baseline / Common validation` only, and other rules, bypass permissions and review requirements are unchanged.
5. Independent Claude exact-head audit of all scope and safeguards; obtain **new explicit owner approval** before merging.
6. Manual `workflow_dispatch` remains available **once workflow is on default branch**; if feasible after owner-approved merge, dispatch manually and verify, clearly distinguishing manual from automatic runs.

## Rollback / stop

If baseline is missing/failing or extra required context returns, stop and investigate; do not use bypass for genuine CI failures. If restoring two required contexts **after E2b merges**, first restore standalone `pull_request` in a reviewed PR while baseline alone remains required; verify `Template integrity` emits and passes on a subsequent real PR; **only then** have the owner re-add it as a required context. Never require a non-emitted check.

M3 generated-project integration and the earlier audit nits remain separate.
