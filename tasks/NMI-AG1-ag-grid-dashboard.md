5. **Money:** amounts are canonical decimal strings. For any numeric money comparison use the existing `minorOf`/BigInt or precise per-currency arithmetic; never `Number`/floating-point comparison of money, never sum different currencies, and never imply an FX-converted total. 6. **States:** retain existing loading, empty, no-match/clear, offline, malformed response, 401 sign-out, 403, load-more (including failed next page), retry, restored filters and search debounce. 7. **Accessibility / mobile:** keyboard navigation through headers, grid and View; correct focus after opening/reopening invoice, 390px mobile layout with no document horizontal overflow, 400% zoom smoke, light/dark contrast, non-mouse usability, readable status/alert text. Keep the full-page flow intelligible to assistive technologies.
8. **Browser security:** no browser persistent storage of customer data; no customer data in navigation URLs/history. ## Audit remediation NMI-AG1-R1 (independent review 5680790512: FIX REQUIRED, 1 MAJOR + 2 MINOR)

The review of `b8a277f03a92736426e9015b9ba906dce983f0ed` found the grid's cell keyboard navigation disabled (MAJOR-1), no visible sorting-scope disclosure (MINOR-1) and an unbounded number of rendered rows (MINOR-2). **Remediation commit:** `f58c4fc27521b25f396ea8a99ac66948a66a5198`; hosted Project Baseline run `40670277117` and Stack CI run `40670276998` **success** on it. The documentation commit after it changes only documentation. Nothing outside `apps/web`, `design/evidence/` and documentation changed; no server, pagination-contract, payment or security change; no real provider call; no merge, deployment or submission.

- **MAJOR-1 fixed (supported APIs only):** `suppressCellFocus` and the custom capture-phase Tab listener, `focusAfter` helper, `setTimeout` handoff and `setFocusedHeader` call are removed. AG Grid's own cell navigation is back: Tab enters the grid on the first column header and Tab / Shift+Tab leave it in one press (`tabToNextHeader` and `tabToNextCell` return `false`, which AG Grid documents as "let the browser handle Tab"), so the grid is one tab stop and never a trap; arrow keys move between headers and cells in every direction, Home/End work, Enter on a header sorts (a second Enter flips direction), and **Enter or Space on the focused Actions cell opens that invoice** (`onCellKeyDown`, handled once; an Enter from the inner button is left to the button). The View button keeps its labelled name but is `tabIndex=-1`, so the cell, not a second control, is the keyboard target; a pointer click on it still works. A visible 2px `:focus-visible` ring was added for cells and headers (AG Grid's own rules had removed the outline). AG Grid scrolls the focused cell into view, which gives keyboard access to the columns beyond a 390px screen. The boundary test now fails if the grid file ever contains `suppressCellFocus`/`suppressHeaderFocus`/`suppressKeyboardEvent`, `setTimeout`, `requestAnimationFrame` or `.focus()`.
- **MINOR-1 fixed:** visible copy above the grid (`#dash-sort-note`, also the grid's `aria-describedby`): "Sorting a column reorders only the N invoices loaded so far. Search and the currency and PayPal status filters look through all your saved invoices." The server pagination contract is untouched.
- **MINOR-2 fixed (defined bound):** `MAX_LOADED_ROWS = 200` in `dashboardState.ts`. Rows stay un-virtualised (every loaded row is a real DOM row in reading order, which is what assistive technology needs, and why row virtualisation was not re-enabled: it hid loaded rows from the DOM and from the journeys), so the bound is on loaded rows: the reducer refuses `load-more` at 200 and the footer replaces *Load more* with an explanation (`#dash-limit`) pointing to search and the currency/status filters, which still search the whole account (shown reaching an invoice that is outside the newest 200). Server cursor paging (limit 20, chained cursor), UUID row ids, loaded-rows-only currency cards and client sort are unchanged. Trade-off to confirm with the owner: beyond 200 unfiltered invoices the list shows only the newest 200 (a UX limit, not a data limit).
