Distinguish grid-local sorting from existing **server-side** currency/status/search filters and keyset pagination; do **not** represent local sorting/filtering as whole-account operations.
5. **Money:** amounts are canonical decimal strings. For any numeric money comparison use the existing `minorOf`/BigInt or precise per-currency arithmetic; never `Number`/floating-point comparison of money, never sum different currencies, and never imply an FX-converted total. When comparing rows across currencies, use a stable explicitly documented currency-first order rather than treating their amounts as interchangeable.
6. **States:** retain existing loading, empty, no-match/clear, offline, malformed response, 401 sign-out, 403, load-more (including failed next page), retry, restored filters and search debounce. Keep the search field mounted while requests are in flight; no extra requests from grid row/column interactions. Currency summary cards are still **loaded-rows-only** and remain independent of grid-local sort. Keep `Load more` and its data append behavior.
7. **Accessibility / mobile:** keyboard navigation through headers, grid and View; correct focus after opening/reopening invoice, 390px mobile layout with no document horizontal overflow, 400% zoom smoke, light/dark contrast, non-mouse usability, readable status/alert text. If the grid cannot meet the approved narrow-layout requirements, retain a proper responsive presentation/fallback (not an inaccessible hidden duplicate). Keep the full-page flow intelligible to assistive technologies.
8. **Browser security:** no browser persistent storage of customer data; no customer data in navigation URLs/history. Dashboard search `q` remains in **HTTP request URL** by existing contract, while Fastify query-string log redaction stays intact; hosted proxy log-redaction remains unverified. Preserve CSP `connect-src 'self'` and no network outside app origin.

- **Grid behaviour:** stable `getRowId` = validated invoice UUID; custom cells for invoice (short id + saved date), customer (name + e-mail), exact total (`formatCurrency` + code), PayPal Sandbox durable status (the shared glyph+text badge) and a native **View** button with the invoice/customer accessible name; sortable and resizable columns (Actions is neither); header sort by mouse or Enter; sort and column widths survive Load more because rows are keyed by UUID. The browser journey asserts no CSP violation, no injected `<style>`, no AG Grid console message, no watermark/Enterprise text, and no data-URI font in the production CSS.
- **Findings during the real-browser run (fixed, not hidden):** AG Grid error #200 until `CellStyleModule` was registered (for `cellClass`); the legacy stylesheet does not define `--ag-auto-height-max-body-height` (set in `app.css`); AG Grid virtualises rows even with `domLayout="autoHeight"`, so a loaded row could be absent from the DOM (`suppressRowVirtualisation` and `suppressColumnVirtualisation` now keep every loaded row and column in the DOM, which also matters for assistive technology); with default cell focus a keyboard user would tab through every cell and with cell focus suppressed Tab looped inside the header row and then skipped the View buttons, so keyboard handling is explicit (below).
- **Keyboard model:** Tab walks the column headers once (Enter sorts, arrow keys move between headers), then moves to the first row's **View** button; each View button is one tab stop in reading order; Tab after the last one continues to *Load more invoices*; Shift+Tab retraces it. Cells are not focus targets (no cell-by-cell arrow navigation). Tab handling on the View buttons is resolved in a capture-phase listener because the grid's own handler otherwise keeps focus on the button. Verified in the journey (bounded Tab count, no forward or backward trap, visible 2px `:focus-visible` ring).
- **Responsive:** at 767px and below the same six columns are re-ordered (Customer, Total, Actions, PayPal Sandbox, Invoice, Due) with fixed widths so the customer, exact total and View action are visible together at 390px without scrolling; the remaining columns are reached by scrolling the grid sideways; the page itself never overflows horizontally (390px dark and light, and a 320 x 256 CSS px viewport emulating 400% zoom on a 1280 x 1024 window).
