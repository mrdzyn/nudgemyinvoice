# P8.0 CI Run Economy — E1 PR-Only Default Triggers

- **Status:** In Progress
- **Owner/orchestrator:** Project owner + ChatGPT

## Objective

Reduce redundant GitHub-hosted runner starts in the master template and future child copies while preserving real required PR validation, least-privilege behavior, and stable emitted required-check identities.

E1 removes automatic `push` validation on `main` from both universal/master-only workflows, keeps `pull_request` validation and adds human-initiated `workflow_dispatch` for exact-branch checks when needed.

## Approved operating assumptions

- This repository protects `main` with required PR checks `Template integrity` and `Project baseline / Common validation`.
- Merged changes already received required PR validation; no production release is authorized by merging.
- An exact post-merge candidate still requires its own validation if a project's release/security model demands it.
- The master template remains a general-purpose starting point: brownfield projects must audit downstream `push: main` dependencies before adopting this trigger change.

## E1 allowed scope

- `.github/workflows/ci.yml` — event trigger only;
- `.github/workflows/template-integrity.yml` — event trigger only;
- `docs/REPOSITORY-SETUP.md` — canonical trigger economy policy/trade-off;
- `docs/STATUS.md`, `docs/HANDOFFS.md`, this task — task and review state.

Everything else is out of scope. The shared `.github/workflows/common-validation.yml`, validators/tests, project profile, AGENTS, release/deployment logic, secrets/OIDC permissions, and live GitHub ruleset must not change in E1.

## Required behavior and acceptance criteria

1. Both workflows run on `pull_request` as before and expose the exact same required job contexts.
2. Both workflows retain the same validation job definitions, master-only repository guard, pinned actions and permissions.
3. Neither workflow automatically runs on `push: main`; both are explicitly invocable using `workflow_dispatch`.
4. No path or branch filters skip required PR checks; existing concurrency cancellation remains.
5. Canonical docs distinguish reducing duplicate CI from skipping required gates, and document manual post-merge/release-candidate validation and brownfield adoption constraints.
6. Hosted PR jobs run and pass against the final PR head, or the documented unavailability exception is independently substantiated. No bypass for real check failures.
7. The master ruleset retains both required contexts. No ruleset mutation, merging, or deployment without owner approval.

## Targeted validation

- Compare workflow files to the base and prove the only executable delta is `push: main` removed and `workflow_dispatch` added.
- Verify `pull_request`, least privilege, pinned checkout, job names, step bodies, master-only guard, and concurrency are unchanged.
- Verify the active ruleset still requires `Template integrity` and `Project baseline / Common validation`.
- Confirm the CI trigger policy and exact post-merge trust caveat in `docs/REPOSITORY-SETUP.md`.
- Open PR and inspect real GitHub-hosted required checks for emitted names and success.
- Obtain independent exact-head review before owner-approved merge.

## Expected runner reduction

For a normal master-template PR merged once, the existing model has two runner jobs on the PR and two on the automatic post-merge `main` push (four starts), while E1 retains the two required PR jobs and removes the two automatic post-merge jobs (two starts). Illustrative **50% fewer automatic runner starts** for that lifecycle, excluding retries/manual dispatch.

Child-project required stack jobs remain project-owned and can add their own runtime.

## Deferred E2 — Master-only Template Integrity consolidation

A later proposal may fold master-only integrity validation into the same runner as the baseline. This would rename/remove the live required `Template integrity` check and therefore **requires an explicit owner-coordinated required-check migration**, independent review, and no period where a required check disappears from `main` unexpectedly. It is not implemented in E1.

## Deferred P8.0 M3

Generated-project pruning/brownfield reconciliation remains M3 scope, including explicitly keeping `.github/workflows/common-validation.yml` and removing master-only Template Integrity. E1 must not silently implement M3.
