## Recorded decision

The project owner selected **Option B**, stating that another human reviewer is not available, and prefers the existing Grok + ChatGPT + Claude + human owner model. The owner selected Option B after explanation that external AI audit and chat approvals do **not** fulfill or become an enforced GitHub `APPROVED` review.

**Residual-risk acceptance for the proposed E2b model:** with a single remaining required baseline context, a PR can remove or weaken the workflow steps that implement master-only integrity yet still emit a successful baseline check. The existing GitHub ruleset requires **zero** approving reviews. A GitHub actor authorized to merge can bypass the required process-only Claude audit and owner approval; the existing PR-only admin bypass is also a residual privilege. The owner knowingly selected this process-only model instead of requiring another human GitHub account.

This is **NOT** approval to change the active ruleset, retire a required status check, merge this PR, or deploy/publish anything. The separate exact ruleset change and workflow PR each require a new explicit authorization at the relevant gate.

## Required Option B operations

1. Start every repo task from `AGENTS.md`, `docs/STATUS.md`, `config/project-profile.json`, the active task, and current handoff, then only relevant files.
2. Implement via Grok or ChatGPT on a feature branch; record bounded scope and targeted tests. Do not merge or deploy automatically.
3. Independently audit **every PR** with Claude on the **exact branch-tip SHA** after implementation, including documentation-only changes. For CI/validator/ruleset/security changes, explicitly challenge tamper potential and whether a required context could be weakened or disappear. Log PASS/PARTIAL/FAIL and severity-ranked findings.
4. Have ChatGPT verify the exact PR SHA, hosted required CI, active ruleset, unresolved review threads, independently audited result, and any release/security boundaries.
5. Obtain **explicit new owner merge approval** after the audit and CI pass. If the commit changes, refresh exact-head CI and independent audit. Do not assert that GitHub mechanically enforces this process.
6. No release, publishing, deployment, or irreversible admin/security action without a separate explicit owner authorization.
7. When a proposed PR weakens master-only validation, fails required checks, or lacks independent exact-head review, **stop**. Existing process-only risk acceptance is not blanket acceptance of actual known validation failures.
